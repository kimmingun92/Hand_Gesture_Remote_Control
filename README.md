# 손동작 인식 기반 원격 PC 제어 시스템

카메라로 손동작을 인식해 다른 PC의 키보드·마우스를 원격으로 제어하는 Edge AI 시스템.
Jetson Nano가 웹캠 영상을 온디바이스로 처리해 동작을 판단하고, 판단 결과(동작 이름)만
소켓으로 Ubuntu PC에 전송해 실제 입력을 실행한다.

`Python` `MediaPipe` `TensorFlow` `Jetson Nano` `PyQt5` `Socket` `PyAutoGUI`

## 배경

누워서 e-book이나 웹툰을 볼 때 화면은 멀리 두고 편하게 보고 싶지만, 손은 계속 기기를
들고 조작해야 하는 불편함이 있었다. 키보드·마우스를 직접 쓰지 않아도 간편한 손동작만으로
화면을 조작할 수 있는 비접촉 인터페이스를 만드는 것이 목표였다.

## 시스템 구성

```
[Jetson Nano]                                    [Ubuntu PC]
웹캠 → MediaPipe → 자세/동작 모델  ──소켓(TCP)──→  인증 → pyautogui 실행
      (좌표 추출)   (인식·판단)                    (키보드·마우스 제어)
```

인식은 Jetson에서 온디바이스로 전부 처리하고, 판단된 동작 이름만 문자열로 전송한다.
서버 연결에 실패해도 Jetson 쪽 인식 자체는 중단되지 않도록 예외 처리했다.

| 장비 | 역할 |
|---|---|
| 로컬 PC | 학습 데이터 수집 (`data_collection/`) |
| Google Colab | 모델 학습, GPU 사용 |
| Jetson Nano | 웹캠으로 손동작 인식 → 서버로 명령 전송 (`jetson_client/`) |
| Ubuntu PC | 명령 수신 → 실제 키보드/마우스 조작 (`server/`) |

## 핵심 설계 — 2단 모델 구조

가장 공들인 부분. 동작 하나만 분류하는 단일 모델로 시작했으나, 동작을 마치고 손을
원위치로 되돌리는 움직임이 반대 동작으로 오인식되는 문제가 반복됐다 (오른쪽 이동 후
복귀하면 왼쪽 이동으로 인식되는 식). 이를 모델을 두 개로 분리해 해결했다.

| 모델 | 입력 | 출력 | 역할 |
|---|---|---|---|
| 자세 모델 | 정지 프레임의 21개 관절 상대좌표 (63개 값) | 준비 자세 5종 | "지금 무슨 동작을 할 준비인가" |
| 동작 모델 | 움직임 구간의 변화량 특징 (13개 값) | 동작 8종 | "방금 무슨 동작을 했나" |

자세 모델이 먼저 준비 자세를 판별하고, 그 자세에서 허용된 동작만 후보로 좁힌 뒤 동작
모델이 판단한다. 예를 들어 검지만 편 `index_ready` 자세에서는 `move`/`scroll`만
후보가 되고 `zoom`이나 `click`은 애초에 나올 수 없다. 여기에 "동작 확정 후 반드시
주먹(중립)으로 복귀해야 다음 동작을 받는다"는 규칙을 더해 복귀 동작으로 인한 오탐을
구조적으로 차단했다.

### 준비 자세 5종 (자세 모델)

| 자세 | 손 모양 | 허용되는 동작 |
|---|---|---|
| `fist` | 주먹 | 없음 (중립 전용) |
| `pinch_closed` | 엄지·검지 붙임 | `zoom_in` |
| `pinch_open` | 엄지·검지 벌림 | `zoom_out` |
| `index_ready` | 검지만 폄 | `move_left` / `move_right` / `scroll_up` / `scroll_down` |
| `click_ready` | 엄지만 위로(따봉) | `click` |

### 동작 8종 (동작 모델)

| 동작 | 수행 방법 | PC에서 실행되는 것 |
|---|---|---|
| `zoom_in` | 꼬집은 상태에서 엄지·검지 벌리기 | `Ctrl` + `+` |
| `zoom_out` | 벌린 상태에서 오므리기 | `Ctrl` + `-` |
| `scroll_up` | 검지 편 채로 아래→위 | `↑` 연속 입력 |
| `scroll_down` | 검지 편 채로 위→아래 | `↓` 연속 입력 |
| `move_left` | 손바닥 편 채로 오른쪽→왼쪽 | `←` 1회 |
| `move_right` | 손바닥 편 채로 왼쪽→오른쪽 | `→` 1회 |
| `click` | 주먹에서 엄지 올렸다 내리기 | 마우스 좌클릭 |
| `idle` | 정지 | 없음 (판단 안 함) |

사용 규칙: **주먹(중립) → 준비 자세 취하고 잠깐 정지 → 동작 수행 → 주먹 복귀 → 반복**

### 특징 설계

좌표를 그대로 쓰지 않고 위치·거리에 무관한 값으로 가공했다.

- **동작 특징 (13개)**: 구간의 시작·끝 좌표 변화량과 속도 기반 (`wrist_dx = 끝_손목x − 시작_손목x` 등). 화면 어디에서 동작하든, 카메라와의 거리가 얼마든 "이동한 정도"만 남아 같은 동작이 같은 패턴으로 모인다.
- **자세 특징 (63개)**: 21개 관절 좌표를 손목 기준 상대좌표로 바꾼 뒤 손 크기로 정규화 (`rel = (관절좌표 − 손목좌표) / 손_크기`). 손이 화면 어디에 있든, 카메라 거리가 어떻든 "손 모양"만 남는다.

## 인식 안정화 장치

오탐을 줄이기 위해 `gesture_worker.py`에 내장된 장치들.

| 장치 | 역할 |
|---|---|
| 움직임 자동 감지 | 고정 시간 윈도우 대신 움직임의 시작/종료를 감지해 구간을 자름 |
| 자세 관성 (hysteresis) | 확정된 자세를 바꾸려면 다른 값이 연속 4프레임 나와야 함 — 노이즈 1~2프레임 무시 |
| 진정 시간 (settle time) | 자세 확정 직후 6프레임 동안은 움직임 감지를 무시 — 자세 취하는 동작 자체가 오인식되는 것 방지 |
| 최종 위치 안정성 | 구간 종료 시 마지막 프레임들의 좌표가 실제로 한 자리에 모여 있는지 검증 |
| 자세 게이팅 | 준비 자세에서 허용된 동작만 후보로 제한 |
| 주먹 복귀 필수 | 동작 확정 후 `fist`를 거쳐야 다음 동작 인식 |

## 모델 성능 (Colab 학습 결과)

| 모델 | 데이터 | 테스트 정확도 |
|---|---|---|
| 동작 모델 (8종) | 800개 (클래스당 100개) | 100% (160개 테스트셋 전부 정답) |
| 자세 모델 (5종) | 1,512개 | 100% (303개 테스트셋 전부 정답) |

두 모델 모두 `Dense`만 사용하는 MLP 구조다. 학습은 Colab의 최신 TensorFlow에서 진행하고,
`model.get_weights()` + `np.savez()`로 순수 numpy 배열만 저장해서 Jetson의 구버전
TensorFlow(2.4.1)에서도 그대로 불러올 수 있게 했다 (아래 트러블슈팅 참고).

## 실행 방법

### 1. 데이터 수집 (로컬 PC)

```bash
conda create -n gesture python=3.12 -y
conda activate gesture
pip install mediapipe==0.10.14 opencv-python==4.9.0.80 numpy==1.26.4 pandas
cd data_collection
python collect_gesture_data.py   # SPACE로 녹화 시작, 1~8로 라벨 저장
python collect_pose_data.py      # 숫자키를 누르고 있으면 해당 자세로 연속 저장
```

결과물 `gesture_features_index.csv`, `pose_features.csv`를 Google Drive에 업로드.

### 2. 모델 학습 (Google Colab)

`training/train_gesture_colab.ipynb`, `training/train_pose_colab.ipynb`를 순서대로 실행
(런타임 GPU 권장). 결과물(`*_weights.npz`, `*_labels.json`, `scaler_params.json`)을
`jetson_client/` 폴더에 `main.py`와 같은 위치로 배치 (이미 학습된 결과물이 레포에
포함되어 있어, 재학습하지 않고 바로 실행만 하려면 이 단계는 건너뛰어도 된다).

### 3. Jetson Nano — 실시간 인식 클라이언트

```bash
sudo apt update
sudo apt install -y python3-pyqt5 pyqt5-dev-tools   # PyQt5는 pip 대신 apt로 설치
pip install mediapipe==0.10.14 tensorflow==2.16.1 opencv-python==4.9.0.80
cd jetson_client
python3 main.py <서버IP> <포트> <내ID> [비밀번호]
# 예: python3 main.py 10.10.16.39 5000 KMG_LIN
```

### 4. Ubuntu PC — 서버

```bash
pip install pyautogui
cd server
cp idpasswd.example.txt idpasswd.txt   # 실제 계정/비밀번호로 수정
python3 gesture_server.py 5000
```

## 트러블슈팅

실제로 막혔던 지점 중 설계에 영향을 준 것들만 추렸다.

### 1. 학습 환경과 배포 환경의 버전 불일치

Colab(최신 TensorFlow)에서 학습한 모델을 Jetson(TensorFlow 2.4.1)에서 불러올 수
없었다. `.keras` 포맷은 Keras 3에서 구조 자체가 바뀌었고, `save_weights()`로 저장한
h5도 "0개 레이어"로 읽히는 등 방식마다 전부 실패했다. GPU 학습 중 생성되는 cuDNN 전용
연산(LSTM의 `CudnnRNNV3`)도 ONNX 변환을 막는 원인 중 하나였다.

**해결**: 프레임워크의 저장 기능을 아예 쓰지 않고 가중치를 순수 numpy 배열로만
추출했다 (`model.get_weights()` + `np.savez()` / `model.set_weights()`). 모델 구조는
학습 코드와 추론 코드에 동일하게 정의해두고 숫자만 옮기는 방식이라 버전 문제가 근본적으로
사라졌다. 같은 이유로 `StandardScaler`도 pkl 대신 mean/scale 값만 JSON으로 저장해
Jetson에 sklearn을 설치할 필요조차 없앴다. LSTM도 GPU 전용 연산이 없는 Dense 기반
MLP로 바꿔 문제 자체를 회피했다.

### 2. 규칙 기반 자세 판별의 한계

관절 좌표의 기하학적 규칙(손가락 펴짐 비율, 엄지 각도 등)으로 준비 자세를 판별하려
했으나, 임계값이 손 크기·카메라 각도에 따라 계속 어긋났다. 검지만 펴도 접힌 엄지와의
거리가 멀어져 "벌린 자세"로 오판되는 등 조건을 추가할수록 예외도 늘어났다.

**해결**: 규칙을 버리고 자세 분류 모델을 별도로 학습했다. 개인차·환경차가 큰 판별은
조건문을 쌓는 것보다 데이터로 학습시키는 쪽이 훨씬 안정적이었다 (5-Fold 교차검증 결과
1,512개 샘플 전부 정확히 분류).

### 3. 오프라인 정확도와 실시간 정확도의 괴리

오프라인 테스트 정확도는 매우 높았지만 실시간 스트리밍에서는 인식률이 눈에 띄게
떨어졌다. 학습 데이터는 사람이 SPACE로 동작의 시작·끝을 정확히 잘라준 구간인 반면,
실시간에서는 "최근 N초"를 고정 윈도우로 기계적으로 잘라 써서 동작 전 정지 구간이나
동작 중간이 섞여 들어갔다.

**해결**: 고정 시간 윈도우 대신 움직임의 시작/종료를 자동으로 감지해 구간을 자르는
방식으로 바꿨다 (사람이 누르던 SPACE를 소프트웨어가 대신 판단). 학습 데이터와 추론
입력의 형태를 일치시키는 것이 모델 성능만큼 중요하다는 걸 확인한 케이스였다.

### 4. 임계값은 추측이 아니라 실측으로

PC에서 잘 맞던 움직임 감지 임계값이 Jetson에서는 손을 완전히 멈춰도 좌표 노이즈가
더 커서 임계값 아래로 안 내려가는 문제가 있었다. 실측값을 화면에 실시간 표시하도록
만든 뒤에야 실제 노이즈 수준을 확인하고 기준을 재설정할 수 있었다. 하드웨어가 바뀌면
알고리즘이 같아도 기준값은 다시 잡아야 한다는 걸 확인했다.

### 5. ARM(Jetson) 환경에서의 패키지 설치

mediapipe, PyQt5 모두 최신 pip wheel이 aarch64(Jetson)를 지원하지 않아 `pip install`이
소스 빌드를 시도하다 실패했다 (PyQt5는 `qmake` 없음 에러). mediapipe는 버전을
`0.10.14`로 고정해서, PyQt5는 pip 대신 `apt install python3-pyqt5`로 시스템에 설치해
해결했다 (`tf241` venv가 시스템 패키지에 접근 가능한 구조라 apt 설치만으로 venv 안에서도
바로 인식됨).

## 한계

학습 데이터가 단일 사용자 기준으로 수집되어 다른 사용자에 대한 일반화는 검증하지
못했다. 손 크기 차이는 정규화로 처리되지만 손가락 비율 등 형태의 개인차는 남아 있어,
실사용을 위해서는 사용자별 캘리브레이션이 필요하다.

## 회고

- **설계는 문제를 없애는 방향으로**: 버전 호환 문제를 계속 우회하려 하기보다 numpy처럼
  의존성 자체가 없는 데이터 형식으로 바꾸자 문제가 근본적으로 사라졌다.
- **규칙과 학습의 경계**: 사람마다 다른 판단(손 모양 개인차 등)은 조건문을 쌓는 것보다
  데이터로 학습시키는 편이 훨씬 견고했다.
- **학습 환경 ≠ 실행 환경**: 높은 검증 정확도가 실사용 성능을 보장하지 않았다. 학습
  데이터와 추론 입력의 형태를 일치시키는 것, 배포 환경에서 실측으로 파라미터를
  재조정하는 것이 필수였다.
